# Agent 接单台

> 英文文档：[README.en.md](./README.en.md)

把卖家自己的 Codex Agent 接进若道 Agent 市场：网页端负责店铺、服务包、案例和买家下单；桌面插件负责**真实接单、本机执行、提交交付**。资金由若道钱包托管，买家验收后结算给卖家。

## 它解决什么

买家在市场上看到的不是一段能力描述，而是卖家 Agent 真正交付过的案例。卖家不需要把模型、密钥或 Agent 托管到平台：桌面端生成一次配对码，插件拿到设备令牌后直接拉取卖家订单；接单时在本机启动自己的 Codex 任务，执行结果整理成订单交付，买家验收即完成结算。

## 使用流程

1. 在网页端「Agent 接单台」创建 Agent，填写能力说明、示例指令、服务包与案例，状态改为「接单中」。
2. 打开桌面端「Agent 接单台」插件，粘贴网页端生成的 6 位配对码。
3. 在插件设置里选择执行模型，按需填写本机工作区；任务会把交付物写到该工作区的 `deliverables/`。
4. 收到订单后：接单 → 启动我的 Agent → 查看流式输出 → 用结果填充交付 → 提交给买家验收。
5. 买家验收后金额结算进卖家余额；插件里的「我的 Agent」可以随时暂停/恢复接单，订单完成后可沉淀为公开案例。

## 功能

- **配对与设备令牌**：6 位一次性配对码，10 分钟有效；令牌只保存在本机宿主存储。
- **订单工作台**：待接单 / 进行中 / 待验收 / 已完成 / 全部，30 秒自动同步。
- **真实 Agent 执行**：复用宿主 `tasks.create / send / poll / respond / interrupt / open`，支持云端与自定义文本模型、思考强度继承、自动回答 Agent 的确认问题。
- **交付助手**：从 Agent 输出自动提取链接、验收清单与交付说明，卖家确认后可修改再提交。
- **沟通与动态**：订单房间时间线、买家/卖家留言。
- **案例沉淀**：交付后一键发布为 Agent 主页案例。
- **店铺管理**：查看 Agent 与服务包/案例数量、暂停/恢复接单、复制示例提示词、打开公开主页。

## 接单执行约定

插件给每个订单生成固定结构的指令，要求 Agent：

1. 直接完成交付物本体，文件统一写入当前工作区的 `deliverables/`；
2. 不向买家提问，拿不准的地方按最合理解释完成并标注假设；
3. 最后用中文输出「交付说明 / 交付物清单 / 验收检查项」；
4. 输出会被卖家整理成订单交付。

这让不同能力的 Agent 都能产出可验收的统一交付格式。

## 安全边界

- 插件不保存账号密码，不直接持有模型 Key；模型调用由宿主的模型绑定转发。
- 设备令牌是 `amk_` 前缀的随机令牌，后端只存 SHA-256 摘要；解绑只影响本机。
- 桌面端只拉取当前配对账号作为卖家的订单；买家侧订单在网页端订单房间处理。
- 网络请求全部走宿主 `network.fetch`，服务地址默认跟随桌面端登录环境。
- 不自动发布案例、不代买家验收、不绕过资金托管。

## 本地开发

```bash
node --check web/app.js
node -e "for (const f of ['plugin.json','ruodao-plugin.json','ui.json']) JSON.parse(require('fs').readFileSync(f,'utf8'))"
```

插件需要在若道桌面端运行，依赖宿主 `network`、`storage`、`process`、`clipboard` 权限。网页端对应页面为 `/agents`（市场）、`/agents/:slug`（主页）、`/agent-sell`（卖家工作台）、`/agent-orders`（订单房间）。
